# Настольные игры с друзьями

Сборник цифровых версий настольных игр для игры с друзьями (Steam / локальная сеть / один компьютер).
Godot **4.7**, GDScript, рендер Forward Plus (d3d12), физика Jolt. Главная сцена — хаб `res://hub/hub.tscn`.

## Структура
- `hub/` — стартовый экран (неоновая комната, коробки игр, пати, приглашения Steam).
  `hub/games.gd` — **реестр игр**: новая игра = новая запись в `HubGames.LIST`. Обложки — `hub/covers/`.
- `games/<id>/` — каждая игра отдельно:
  - `logic/` — чистые правила без UI (`*_rules.gd`, `*_data.gd`, боты `*_bot.gd`). Всё тестируемо headless.
  - `ui/` — `main.tscn` → `*_app.gd` (корень: меню / лобби / стол), `*_lobby.gd`, `*_table.gd`, `*_style.gd` (мини-дизайн-система игры).
  - `art/`, `audio/` — ассеты игры.
  - Префиксы файлов по игре: `dw_` dangerous_words, `br_` brodilka, `gl_` gloom, `hc_` hues_and_cues, `nh_` not_a_hat, `rsb_` ready_set_bet, `tt_` tip_top, `wl_` wavelength, `ws_` word_slam, `st_` stillion; у king_of_12 и perudo — без префикса / `perudo_`.
- `games/king_of_12/` — первая игра, из неё выросли **общие автозагрузки**: `Net` (net/net.gd), `Sfx`, `Prefs` (audio/), `K12UI` (ui_kit), `K12Tavern`. Их используют все игры.
- `docs/` — ТЗ на каждую игру (`TZ_<игра>.md`), `ui_tips.md`, `visual_design.md`, стайлборды `styleboard_*.png`, `КАК_ИГРАТЬ.md`.
- `tests/` — автотесты правил, `tools/` — служебные сцены (фазз, скриншоты, компиляция).
- `addons/godotsteam` — GodotSteam. `build/` — экспорт (в .gitignore).

## Сеть (Net) — важно
- Вся логика партии выполняется на **хосте** (peer 1). Клиенты только шлют `Net.send_action(...)` и получают своё состояние через сигнал `state_changed(view)`.
- Режимы: `offline` / `enet` / `steam`. Игры из `Net.LOCAL_GAMES` в офлайне — местные игроки (hot-seat), остальные — с ботами.
- Настройки всех игр лежат в `Net.settings` (ключи с префиксом игры). Новая игра → добавить свои ключи и, если нужно, в `LOCAL_GAMES`.
- Steam — только через `Engine.get_singleton("Steam")`: в редакторе аддон не грузится, код обязан работать без него.

## Как добавить новую игру
1. ТЗ в `docs/TZ_<id>.md` (по образцу существующих), при смене стиля — стайлборд на согласование.
2. `games/<id>/logic/` — правила + данные + (бот), затем `tests/test_<id>.gd`.
3. `games/<id>/ui/` — app / lobby / table / style + `main.tscn`, по образцу `games/perudo/ui/`.
4. Подключить к `Net` (действия, view для каждого места, настройки) и записать в `hub/games.gd`.
5. Прогнать тесты, compile и фазз (ниже).

## Проверки
```
# тесты правил одной игры (код выхода 1 при ошибке)
godot --headless --path . --script res://tests/test_perudo.gd
# все скрипты компилируются
godot --headless --path . res://tools/_fuzz/compile.tscn
# фазз-партия: env GAME, SCENE, BOTS, SPEED, MS, DARK=1, RESTART=1
godot --path . res://tools/_fuzz/fuzz.tscn
```
Тесты — простые `extends SceneTree` с `check(cond, msg)`, без фреймворка. Правила king_of_12 — `tests/test_rules.gd`.
- **Звук на тестах выключен.** При любых проверках (тесты, compile, фазз, скриншоты, runtime-сценарии), кроме проверок самого звука, игра не должна шуметь: запускать Godot с `--audio-driver Dummy` (headless и так без звука). Настройки звука игрока (`Prefs`) для этого не трогать.

## Стиль кода и UI
- Комментарии, строки UI, сообщения тестов — **на русском**. Док-комментарии `##` в начале файла: что это и как запускать.
- Типизированный GDScript (`var x := ...`, `-> void`), табы, `class_name` у логики (`PerudoRules`, `GLRules`…).
- UI строится в коде (сцены `main.tscn` минимальные), стили — в `*_style.gd` игры.
- Дизайн: 1 шрифт-заголовок + 1 текстовый, ≤3 размера, 2 основных цвета + нейтральные, сетка 8 px, один главный CTA, светлая и тёмная тема (`Prefs.theme_mode`). Подробно — `docs/ui_tips.md`, `docs/visual_design.md`.

### Чек-лист внешнего вида (проверять на каждом новом/изменённом экране, по скриншоту)
1. **Сначала раскладка, потом цвет.** Иерархия читается в ч/б: что главное, что вторично — видно по размеру и весу.
2. **Палитра ≤ 3–5 цветов:** главный, акцент (только для главного действия/выделения), нейтральные. Серые и чёрные — слегка подкрашены под тему игры; без чисто белых плашек на тёмном/цветном фоне (белое «выпрыгивает»).
3. **Воздух.** Отступы щедрые и одинаковые (шаг 8 px): внутри панелей ≥ 12–16, между группами больше, чем внутри группы. Ничего не прилипает к краю экрана.
4. **Свет сверху.** Выпуклое (кнопки, карты, окна) — мягкая тень снизу; вдавленное (поля, нажатое) — внутренняя. Тени слабые, обводки полупрозрачные и в тон заливке.
5. **Текст.** Читаемый нейтральный шрифт для текста, декоративный — только заголовки. Без тонких начертаний. Контраст с фоном достаточный; текст на картинке — на подложке/затемнении. Второстепенное «гасим» (меньше, светлее), главное — один заголовок.
6. **Кнопки.** Одна главная (яркая, крупная), остальные приглушены; опасные («Выйти», «Покинуть пати») — тихие и подтверждаются удержанием: зажать — кнопка заполняется, выход по заполнению (`LeaveGuard.wire` / `LeaveGuard.hold`, заливка — `hub/hold_fill.gd`); окно `LeaveGuard.ask` — только для других важных действий. Выбранное — заливкой (`UISel`), наведение — цветом/тенью, без изменения размера.
7. **Иконки** — плоские, одноцветные, одного набора. Эффекты (градиенты, блюр, свечение) — только как акцент.
8. **Обратная связь.** Каждое нажатие что-то показывает/звучит; всегда видно, чей ход и какая фаза; журнал/лог для сложных игр.
9. **Единообразие.** Одинаковые элементы одинаковы во всей игре; цвет закреплён за смыслом (мой ход, успех, ошибка); механика карт/кубиков — общая (`K12TableCard`, кубики).
   - **Карты в интерфейсе** (рука, ряд на столе, мини-карты в панелях, карты на поле): при наведении — крупный просмотр рядом, как в Gloom (`gl_table.gd: _show_preview`, `br_table.gd: _hoverable`). Подсказки-тултипы с текстом карты вместо этого не годятся.
   - **Кубики — везде 2D, `TossDie` (`hub/toss_die.gd`, образец — `br_table.gd`):** плоский кубик с физикой монетки. Бросок игрока: схватить, потянуть и отпустить; сила броска — от того, как резко тянул; результат приходит с хоста, кубик останавливается на нужной грани. Пока бросать нельзя — кубик полупрозрачный и неактивный; когда твой бросок — яркий, его надо бросить мышью. Чужой бросок и бросок «дома»/бота — тот же кубик летит сам (`throw`). 3D-кубики (`K12Die3D`) в новых экранах не использовать.
10. **Проверка.** Смотреть скриншот в светлой и тёмной теме и в 1280×720: ничего не перекрывается, всё читается без приближения.

### Верхняя полоса стола (TopBar) — во всех играх
- Все общие элементы стола — только в полосе `hub/top_bar.gd` (`TopBar.make(...)`, образец — `br_table.gd`): слева мелкое название игры прописными + часы хода + гнездо монетки-антистресса, под ними крупно ход/раунд (`_top.info`); справа «Чат», «Пауза» (хост), «Пригласить», «Зритель» и кнопки игры в `_top.actions` (Правила, Настройки, тема, Журнал, тихая «Выйти» с `LeaveGuard`).
- Фон полосы — фон самой игры (передать `null` → прозрачная, снизу тонкий разделитель). Стол начинается ниже на `TopBar.HEIGHT`; ничего общего не рисовать поверх поля. Чат — выпадающий `_top.chat`.
- Инструкция по переносу — `docs/topbar_rollout.md`.

### Игры с полем (ходилки; образец — `games/brodilka/ui/br_table.gd`)
- **Поле** — одна большая картинка в окне с обрезкой (`clip_contents`): зум колесом к курсору, перетаскивание любой кнопкой мыши; масштаб не меньше «всё поле влезает». Снизу поле можно увести за край на высоту панели хода, чтобы крайние клетки не прятались под ней.
- **Камера** сама плавно едет к фишке того, кто ходит/кого сдвинули; если игрок только что двигал поле — 5 с не мешаем. Клик по строке игрока — показать его фишку.
- **Клетки** — в логике линейный список (`*_board.gd`: коды клеток + центры в долях картинки); перекрёсток — клетка, через которую дорожка проходит дважды. Разметка: на глаз по четвертям + проверка наложением точек с номерами на картинку (скрипт PIL), правки — `tools/br_mark.gd`.
- **Фишки** — вырезанные персонажи с тенью и кольцом цвета игрока; вперёд — шагом по каждой клетке с подскоком, назад/телепорт — прыжком по дуге; несколько на клетке — рядом. Фишка хода покачивается.
- **Печатные места на поле** (колоды, ячейки карт) заполняются настоящими картами, но всё важное дублируется в боковой панели — край поля часто за кадром.
- Справа: игроки (портрет, ресурсы, карты), общий ряд карт, журнал; снизу по центру поля — одна главная кнопка фазы; выбор — окном в центре поля; вытянутая карта — крупно на 2 с.
- Ассеты из мода Tabletop Simulator (`Mods/Workshop/<id>.json`): ссылки `cloud-3.steamusercontent.com` отдают 403 — качать с `https://steamusercontent-a.akamaihd.net/ugc/...` (curl с User-Agent). Листы колод 10×7, кол-во копий — по `DeckIDs`.

## Решения, ошибки, ревью
- **`DevDecisions.md`** — когда пользователь решает спорный вопрос (выбирает вариант, поправляет подход, говорит «так не надо, делай так») — сразу запись: ситуация → решение (почему) + дата. Новая просьба противоречит записи — главнее просьба, запись обновить.
- **`rulebook.md`** — если нейросеть (Claude или Codex) совершила одну и ту же ошибку второй раз — правило: ошибка → как правильно → как проверить.
- **Двойная разработка Claude ⇄ Codex:**
  - Claude разрабатывает/добавляет функцию → передаёт Codex: Codex прогоняет тесты и делает ревью.
  - Codex разрабатывает → ревью и проверку делает Claude.
  - Передача — запись в `REVIEW_QUEUE.md` (шаблон в файле): что и зачем, файлы, как проверить (команды тестов, что смотреть в игре), риски. Тот же текст — короткий блок «Для Codex» / «Для Claude» в конце ответа пользователю, чтобы его можно было переслать.
  - Ревьюер: читает изменения, запускает тесты и compile, дописывает в запись итог — «принято» или замечания (файл:строка, что не так). Исправляет автор, затем повторное ревью. Мелкие правки одной сессии можно объединять в одну запись.
