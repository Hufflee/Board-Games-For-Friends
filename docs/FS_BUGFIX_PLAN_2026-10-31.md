## 1. Цель («готово»)

Критерий из FS_TESTING_HANDOFF (27.10), его и держимся — **не** автоматизация всех 913 карт:

1. Партия 2–8 игроков (база и DLC) доходит до победы **без зависаний, потери состояния и рассинхрона** — локально, ENet, Steam.
2. Базовые правила (ход, стек/ответы, бой, смерть и штраф, магазин, души, лимит руки) работают всегда.
3. Каждая карта имеет статус **auto / partial / manual**. Карта manual/partial явно помечена в UI, и панель эффекта
   умеет выразить её текст доступными операциями. «Не автоматизировано, но выполнимо руками» — **не баг**.
4. Баг = нарушение п.1–3: зависание, неверная зона/копия карты, утечка монет, неверное возобновление, автоматика
   срабатывает не так/дважды, панель не может выразить текст карты, рассинхрон view/кнопок с правилами.

## 4. Этап 1 — тестовая инфраструктура (главный множитель скорости)

Всё в `tests/fs/`. Старые 57 тестов **не переписываем сразу**: они становятся группой `legacy` в раннере и
страхуют рефакторинг. Тест, сломавшийся из-за рефакторинга, переносится в новый формат.

### 1.1 `FSScenario` — построитель состояния (`tests/fs/fs_scenario.gd`)
```gdscript
var g := FSScenario.new().players(2).current(0) \
	.hand(1, [478, 479]).item(0, 34).monster(0, 396, {"hp": 3}) \
	.coins(0, 5).build()          # раздаёт недостающее из колод, банк = 100 − выданное
```
Заменяет 9 разных `make()/fixture()`; после `build()` сразу проверяет инварианты (1.3).

### 1.2 Драйвер действий
- `s.ok(seat, kind, arg, "что ожидаем")` / `s.no(...)` — действие принято/отклонено (+ revision изменился/нет).
- `s.roll(face)` — детерминированный кубик через **шов в FSRules**: `var roll_source: Callable` (по умолчанию `_rng`).
  Убирает подмены результатов в каждом тесте.
- `s.close_responses()` — единственное место, знающее про `_finish_responses()`; после рефакторинга меняется одна строка.
- `s.expect(path, value)` — сравнение по пути (`"players.1.coins"`) с понятным сообщением.

### 1.3 `FSInvariants.check(game) -> Array[String]` (глобальная функция, `games/four_souls/logic/fs_invariants.gd`)
Вызывается **после каждого действия** в тестах, фаззере и (в debug-сборке) на хосте:
- монеты: `bank + Σcoins == 100`;
- каждая физическая карта ровно в одной зоне (колоды, сбросы, руки, предметы, монстры, магазин, души, проклятия, стек, peek);
- `0 ≤ hp ≤ max_hp`, `souls == soul_cards.size()`, фаза из известного списка, `actor()` валиден;
- **анти-зависание**: если партия не окончена, `legal_actions(seat)` не пуст хотя бы у одного места;
- приватность: `get_view(s)` не содержит id чужих закрытых рук/peek.

Один этот файл ловит целые классы прошлых багов (Тряпочник, Визуб, Проглоченный пенни, зависания штрафа).

### 1.4 `FSRules.legal_actions(seat) -> Array[Dictionary]`
Единый источник «что сейчас можно». Используют: инвариант анти-зависания, фаззер, **и UI** (кнопки/подсветка) — D6 исчезает.

### 1.5 Фаззер правил (`tests/fs/fs_fuzz.gd`, headless, без UI)
Случайные законные действия из `legal_actions` + случайные операции панели эффекта; 2/4/8 мест, DLC вкл/выкл, N сидов.
При падении инварианта — сохраняет сид и журнал действий, **автоматически укорачивает** (выкидывает действия, пока ошибка
воспроизводится) и пишет готовый регресс-кейс в `tests/fs/regress/`. Заменяет «60 партий / 128475 проверок».

### 1.6 Карточные кейсы таблицей (`tests/fs/cases/*.gd`, массивы-константы)
```gdscript
{"card": 358, "name": "Тряпочник: 6 после награды → наверх колоды",
 "setup": {"reward": 358}, "do": [["effect", 0, {"op": "loot", "amount": 1}], ["roll", 6], ["effect_done", 0]],
 "expect": {"zone_of": [358, "monster_deck_top"]}}
```
Один раннер на все строки. Фикс бага = одна-две строки (позитив + негатив), а не новый файл с наследованием.

### 1.7 Раннер `tests/fs/run.gd`
Группы `core` (< 30 с), `cards`, `regress`, `fuzz`, `legacy`, `ui` (headless TableDriver), `net` (ENet-скрипт).
`--group`, `--filter`, одна строка итогов на группу, код выхода 1 при ошибке, логи — в `build/fs_tests/`.
Агенту достаточно: `godot --headless --audio-driver Dummy --path . --script res://tests/fs/run.gd -- --group core,cards`.

**Приёмка этапа 1:** legacy проходит как раньше; фаззер 500 партий без падения инвариантов (или каждый найденный —
строка в FS_BUGS); 10–15 известных багов из реестра оформлены кейсами (красные/зелёные — как есть).

## 5. Этап 2 — рефакторинг ядра без смены поведения (Opus / Sol medium)

Страхуют: legacy + кейсы + фаззер с инвариантами. Делать мелкими шагами, после каждого — `core,cards,legacy,regress`.

1. **Продолжения вместо маркеров** (`fs_flow.gd`): явный стек продолжений `[{kind: "end_turn_step", step: 3}, {kind: "resume_roll", …}]`
   вместо `_after_stack/_death_resume/_turn_resume/_ending_turn/_end_after_deaths/paused_effects`. Любое прерывание
   (ответ, смерть, пассив, ручной выбор) кладёт продолжение; после разрешения берётся верхнее. Это корень D2.
2. **Ход как список шагов** (`fs_turn.gd`): start-триггеры → перезарядка → добор лута → действия → end-триггеры →
   перезарядка конца → лечение → сброс до лимита. Каждый шаг — событие на шине (см. 3).
3. **Модули** по ~200–400 строк: `fs_stack.gd` (окно ответов/LIFO), `fs_combat.gd` (атака, бросок, урон, PvP),
   `fs_death.gd` (смерть, штраф, замещения), `fs_effects.gd` (ручные операции), `fs_view.gd` (get_view).
   FSRules остаётся фасадом с тем же `action()/get_view()` — сеть и UI не трогаем.
4. **Операции панели — таблица** `OPS := {"coins": {"params": [...], "apply": Callable}}`: сервер исполняет, UI строит поля
   из того же описания → не будет «угаданных» операций (rulebook monster_dc).
5. **Карточные хуки** `games/four_souls/logic/cards/` : `CARD_HOOKS := {396: Pride, 429: Peep, 715: Ambush, 358: Ragling, 268: Conquest …}`
   с методами `on_attack_declared / on_reward / on_death / on_roll`. В ядре не остаётся `if id == 396`.
6. **Шина событий**: добавить `turn_start, loot_draw, purchase, monster_damage, item_destroyed, soul_gain, item_gain, before_death`
   с документированным контрактом `data` в FS_CARD_EFFECTS.md.

**Приёмка:** все группы зелёные, ни одна строка FS_BUGS не изменила статус «случайно», ENet 1 партия.

## 10. Экономия токенов

- Агент читает `FS_BUGS.md` + один модуль 200–400 строк, а не 75-КБ `fs_rules.gd` и 2 МБ отчётов.
- Итог раннера — одна строка на группу; логи в `build/fs_tests/`, читаются только при падении.
- Тексты карт — из `card_texts.json`; изображение открывается один раз при верификации.
- Фаззер сам находит и минимизирует баги — нет ручных многочасовых UI-прогонов ради поиска.
