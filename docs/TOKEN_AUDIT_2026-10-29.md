# Аудит расхода после продолжения29.10

Показатель API на момент вопроса владельца:45%короткого окна,38%недельного. Это доля общего лимита аккаунта, не точный счёт токенов конкретной задачи. Пятичасовое окно — период лимита, а не обещание пяти часов непрерывной работы.

Прочитаны только записи метаданных `token_count`/`turn_context` трёх известных сессий с00:40UTC29.10. Разница накопительных счётчиков относительно последней записи до начала периода; повторные одинаковые отчёты исключены. Содержимое сообщений пользователя в отчёт не переносилось.

Суммарно:32 329 308 входных,31 459 968 кэшированных,869 340 входных без кэша,74 169 выходных. Это накопленный объём запросов, **не размер уникального проекта и не32миллиона новых оплачиваемых токенов**. Точный перевод в45%лимита и распределение процентов по агентам по этим файлам недоступны.

Последний контекст запроса: координатор~422тыс., исполнитель~154тыс., проверяющий~393тыс. Большие старые истории проходят через много обращений даже при высокой доле кэша. Ускорение тремя потоками не гарантирует экономию; эталонного однопоточного прогона той же задачи нет.

Выявлено несоответствие: роль проверяющего называлась Sol low, однако `turn_context` в проверенном периоде фиксирует `gpt-6.1-sol / effort=medium`. Результаты тестов сохраняют силу, но прежняя характеристика вычислительного режима low для этого периода неверна. Это ошибка проверки эффективной конфигурации, а не доказательство дефекта модели.

Количество утверждений локального Godot-теста не равно количеству обращений к модели. Расход возникает при подготовке/изменении harness, чтении результатов, размышлении и повторной передаче контекста. В пакетах ESC/PI были также ошибки подготовки тестов и повторные проходы; это дополнительная нагрузка, а не главный измеренный размер входа.

Предлагаемый режим: короткая основная сессия с актуальным handoff; свежие ограниченные субагенты без наследования всей истории (`fork_context=false`); явные `reasoning_effort=medium` для реализации и `low` для проверки с контролем `turn_context`. Для малых задач не держать постоянно три потока: последовательная реализация и один ограниченный review. Не менять модель без разрешения владельца. Текущие пакеты сохранены, новые в ходе аудита не запускались.
