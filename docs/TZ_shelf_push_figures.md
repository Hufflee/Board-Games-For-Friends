# Взаимное сдвигание предметов шкафа

Основание: незавершённый пункт пакета27.10 — переносимая фигурка должна раздвигать коробки и другие фигурки; коробка должна сдвигать фигурки. Перенос разрешён между подходящими ячейками, а не только внутри исходной.

Граница изменения: `hub/neon_room.gd`, `hub/shelf_config.gd`, при необходимости `hub/shelf_layout.gd` и адресные тесты. Размеры, модели, позы и запуск игр не переделывать.

Причина нынешнего ограничения: `ShelfConfig.row_layout` выделяет фигурки в отдельные закреплённые интервалы по `figure_positions`, исключая их из списка стопок. `_drag_update` отдельно обрабатывает фигурку и дописывает её в конец ряда. Поэтому обычная вставка по `pile_insert_index` не меняет положение фигурки как соседа.

Нужен единый порядок соседей при переносе. Фигурка занимает собственную ширину и не становится частью стопки. Лежащие коробки сохраняют существующее объединение в стопки. Измерение вместимости, изображение, предпросмотр, сохранение и упаковщик `solve/_pack` должны использовать одну геометрию; нельзя исправить только видимое положение.

Старая расстановка загружается без внезапной перестановки. При первом ручном изменении порядок соседей должен соответствовать их видимому расположению, а старый коэффициент свободного положения фигурки не должен оставаться неподвижным препятствием. Способ миграции выбирает исполнитель; отмена жеста и редактора обязана восстанавливать исходное состояние, включая предпочитаемые места.

Минимальные сценарии:

1. Фигурка проходит справа налево через стоящие коробки: они сдвигаются вправо, перекрытий нет.
2. Фигурка проходит слева направо: соседи сдвигаются влево, обратное движение возвращает корректный порядок.
3. Коробка проходит через фигурку в обе стороны: фигурка сдвигается как обычный сосед.
4. Две фигурки меняют порядок между коробками; ни одна не входит в другую или в стопку.
5. Фигурка вставляется перед/после горизонтальной стопки; стопка сохраняет внутренний порядок и высоту.
6. Перенос между разными ячейками работает при допустимых размерах. При нехватке места отпускание возвращает весь предпросмотр, без потери предметов.
7. «Отмена» редактора, обычная отмена переноса и сохранение/перезапуск сохраняют корректный порядок и ровно один экземпляр каждого ID.

Проверка: узкие тесты геометрии плюс существующая регрессия шкафа; один настоящий UI-сценарий переноса фигурки и коробки мышью с кадром1280×720. Dummy и отдельный APPDATA.
