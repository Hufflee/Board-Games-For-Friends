# Редактор настольных игр — ТЗ (дизайн-документ)

Дата: 01.11.2026. Статус: **фундамент этапов 1–3 проверен Codex; прототипы этапов 4–7 доступны через ТВ: компоненты, раскладка, цепочки, локальная отладка, 3D-коробка со слоями и запеканием. Ряд функций ещё впереди; MVP не готов. Отчёты EDITOR_STAGE4_6 и EDITOR_STAGE7_2026-11-01.md. Независимое ревью Claude не состоялось из-за ошибки авторизации CLI.** Ответы владельца на уточняющие вопросы — в разделе 0, они же записаны в `DevDecisions.md` («Редактор игр»).

Цель — встроенный в сборник редактор, в котором игрок без программирования собирает свою настольную игру: коробку на полку, компоненты (карты, кубики, жетоны), экран стола и правила из блоков. Созданная игра появляется в шкафу хаба как обычная и играется с друзьями по сети (хост авторитетен, как во всех играх сборника).

## 0. Решения владельца (01.11.2026)

| Вопрос | Решение |
|---|---|
| Вход | Телевизор в комнате хаба, надпись «Редактор» на экране. |
| Раскладка | Как в Photoshop: в центре рабочее поле, слева инструменты, справа панели свойств, сверху 4 вкладки. |
| Логика | **Гибрид**: событие-«шапка» и под ним цепочка блоков-пазлов, соединённых линией; значения (игрок, карта, число) вставляются в гнёзда блока. Не «паутина» Blueprints и не чистый Scratch. |
| Раздача игры друзьям | **Хост передаёт сам**: при входе в лобби клиенты автоматически докачивают игру у хоста. Экспорт/импорт файлом и Steam Workshop — позже. |
| MVP | **Простая карточная игра**: все 4 вкладки в урезанном виде; цель — собрать игру уровня простой карточной/«Перудо» и сыграть по сети. |
| Боты | **Нет в MVP.** Только живые игроки (сеть или hot-seat). Архитектура сразу перечисляет разрешённые действия, чтобы бот «случайный допустимый ход» потом был дешёвым. |
| Размер коробки | **Шаблоны форм + ползунок толщины**, гарантированно помещается в шкаф. |
| Экраны ролей | **Оба способа**: одна общая раскладка с видимостью элементов по ролям (MVP) + возможность сделать для роли полностью свой экран (после MVP). |
| Шрифты | **Только свободные OFL с кириллицей** (встроенный набор), плюс свои шрифты пользователя. |
| Свобода игроков | **Правила + «ручной режим»**: действия разрешает логика, но автор может пометить зону/колоду «свободной» — там игроки двигают компоненты руками. Игру можно собрать вообще без логики (песочница). |
| Лица карт | **Шаблон + таблица**: один шаблон карты с полями, строка таблицы = карта; поля доступны логике. Плюс импорт готовых картинок/листов. |
| Проверка игры | **«Играть за всех»**: кнопка «Проверить» — офлайн-партия с переключением мест и панелью отладки. |
| Права на ассеты | **Ответственность автора**: предупреждение при первом импорте, у ассета поле «источник/лицензия». Игры ходят только по сети между друзьями, публичного каталога нет. |

## 1. Цели и границы

### 1.1 MVP (первая рабочая версия)
- Вход через ТВ, список «Мои игры» (создать / открыть / дублировать / удалить удержанием).
- **Коробка**: 3D-коробка выбранного шаблона, слои-картинки и текст, базовые фильтры, запекание граней → коробка в шкафу.
- **Элементы**: колоды карт (9 размеров, шаблон + таблица, рубашка, импорт листа), кубики d6 (цвет, свои грани, по игрокам/командам), жетоны/монеты, счётчики-ресурсы, панель игрока.
- **Интерфейс**: один экран стола 16:9 с обязательным TopBar; зоны (колода, стопка, ряд, веер-рука, сетка, свободная), панель «Я» и автоматическая полоса соперников, кнопки, счётчики, текст, лоток кубиков, журнал. Видимость элемента по ролям и «Смотреть как…».
- **Логика**: фазы и порядок ходов, события, ~45 базовых блоков (раздел 5), переменные (общие, у игрока, у команды), проверка ошибок, отладка в режиме «Проверить».
- **Игра**: игроки 2–8, команды, роль «Ведущий»; партия по сети (offline hot-seat / ENet / Steam) с автодокачкой игры с хоста; переподключение; зрители.

### 1.2 После MVP
- Свои экраны для ролей; секретные роли.
- Бот «случайный допустимый ход», затем бот из блоков.
- Игровые поля-ходилки (дорожка клеток, фишки — по образцу `br_table.gd`), многогранные кубики d4–d20.
- Настройки партии, задаваемые автором (появляются в лобби), таймеры, свои звуки.
- Экспорт/импорт файла `.pgame`, сохранение копии полученной игры (если автор разрешил), Steam Workshop.
- Свои функции (блок-«процедура»), списки, анимации, шаблоны-примеры игр.

### 1.3 Не делаем
- Произвольный код (GDScript/Lua) в играх — только интерпретируемые блоки (безопасность, см. 7.4).
- 3D-стол. Всё на столе — 2D, как в остальных играх сборника.
- Публичный каталог чужих игр.

## 2. Вход и общая раскладка редактора

### 2.1 Вход
- На экране телевизора в комнате хаба — постоянная неоновая надпись **«Редактор»**; клик по экрану — переход в редактор (через обычный `scene_transition`).
- Сейчас клик по ТВ переключает каналы (решение в `DevDecisions.md`, «Хаб»). Предложение: каналы — колесом мыши над ТВ или маленькой кнопкой на тумбе. **Открытый вопрос владельцу** (раздел 11).
- Первый экран — «Мои игры»: карточки игр (миниатюра коробки, название, дата правки, значок ошибок логики), главная кнопка «Новая игра», шаблоны «Пустая», «Карточная», «С кубиками» (после MVP — примеры).

### 2.2 Раскладка (как в Photoshop)
```
┌──────────────────────────────────────────────────────────────────────┐
│ ← Мои игры  «Название»   [Коробка][Интерфейс][Логика][Элементы]  ↶ ↷  Сохранено ● [Проверить] │
├────┬─────────────────────────────────────────────────────┬───────────┤
│ T  │                                                     │ Панели    │
│ o  │               РАБОЧЕЕ ПОЛЕ                          │ (Слои /   │
│ o  │      (зум колесом к курсору, панорама средней/      │ Свойства /│
│ l  │       правой кнопкой или пробел+ЛКМ)                │ Библиотека│
│ s  │                                                     │ / Ошибки) │
├────┴─────────────────────────────────────────────────────┴───────────┤
│ Строка состояния: подсказка инструмента · масштаб · ошибки: 2 ⚠ 1 ✖   │
└──────────────────────────────────────────────────────────────────────┘
```
- **Сверху** — 4 вкладки-категории в порядке владельца: Коробка · Интерфейс · Логика · Элементы. Переход свободный; вкладки, которые зависят от элементов, показывают пустое состояние «Сначала добавьте элементы» со ссылкой. Справа — отмена/повтор, индикатор сохранения, главная кнопка **«Проверить»** (единственный яркий CTA).
- **Слева** — узкая вертикальная панель инструментов, своя у каждой вкладки (иконки одного плоского набора, подсказка с горячей клавишей).
- **Справа** — сворачиваемые панели, ширина 280–360 px, перетаскиваемый разделитель.
- **Снизу** — строка состояния; клик по счётчику ошибок открывает панель «Ошибки».
- Разрешение 1280×720 — минимально поддерживаемое; панели сворачиваются в иконки.
- Стиль редактора — неоновый стиль хаба (`hub_style.gd`), светлая и тёмная тема (`Prefs.theme_mode`). Сетка 8 px.
- **Отмена/повтор** — общий стек команд на игру (Ctrl+Z / Ctrl+Y), глубина 200. **Автосохранение** — при смене вкладки, каждые 60 с и при выходе; последние 10 версий в `history/`.
- Выход из редактора — тихая кнопка «← Мои игры», при несохранённых изменениях — сохранить автоматически (без диалога).

## 3. Вкладки

### 3.1 Коробка
**Что видит пользователь:** в центре — 3D-модель пустой коробки (светло-серый картон, без спрайтов) на нейтральном фоне, вращается перетаскиванием ПКМ, зум колесом.

**Шаблоны формы** (решение владельца): ползунок толщины + 4 формы. Конкретные габариты берутся из системы шкафа (`shelf_config.gd`, `neon_room.gd`: сейчас коробка 0,3×0,3 с толщиной `thickness` из `HubGames`, нестандартные — у Тип Топа/Айзека):

| Шаблон | Ширина × высота (лицо) | Толщина |
|---|---|---|
| Квадратная (стандарт) | 0,30 × 0,30 | 0,04–0,12, по умолчанию 0,06 |
| Высокая | 0,24 × 0,32 | 0,04–0,10 |
| Широкая | 0,32 × 0,24 | 0,04–0,10 |
| Малая карточная | 0,18 × 0,22 | 0,04–0,08 |

Значения сверяются с допусками ячеек шкафа при реализации; шкаф уже умеет укладку разных размеров.

**Слои.** Как в фоторедакторе: список слоёв справа (перетаскивание — порядок, глаз — видимость, замок, удалить). Типы слоя: картинка (PNG/JPG/WebP, несколько штук), текст, заливка цветом/градиентом.
- **Режим «грань»**: кнопки Лицо / Задник / Корешок / Верх — камера плавно встаёт строго перед гранью, слои редактируются в 2D в плоскости грани. Часть слоя за пределами грани показывается полупрозрачной (35 %), часть на грани — полностью. При запекании остаётся только то, что на грани; остальное отбрасывается.
- **Перенос через ребро** (после MVP): слой можно «загнуть» на соседнюю грань — для картинки во всю коробку.
- **Трансформация**: перемещение, масштаб (Shift — пропорционально), поворот (рамка с ручками, Shift — шаг 15°), отражение, выравнивание по центру/краю грани, привязка к сетке и центру.
- **Коррекция** (у каждого слоя, ползунки со сбросом двойным кликом): прозрачность, яркость, контраст, насыщенность, экспозиция, затемнение (умножение на тёмный цвет), оттенок; после MVP — размытие, тень/свечение у текста, режимы наложения. Реализация — шейдер слоя, исходный файл не меняется.
- **Текст**: шрифт (встроенный набор или свой), размер, цвет, обводка, тень, межбуквенный интервал, выравнивание, многострочность.
- **Подсказки качества** (по `DevDecisions`, «Хаб»): предупреждение, если яркость/насыщенность лица сильно ниже соседних коробок; если задника нет — задник = копия лица.
- **Запекание**: при сохранении каждая грань рендерится в `SubViewport` → `covers/front.png`, `back.png`, `spine.png`, `top.png` (по 1024 px по длинной стороне) — те же части, что и у встроенных коробок (`hub/covers/<id>_front|_back|_spine`). Цвет коробки (`color`) — средний цвет корешка, можно поменять вручную.
- Справа также: название, число игроков, время партии, описание — то, что видно в хабе у коробки (поля как в `HubGames.LIST`).

**Сценарий:** «Новая игра» → «Коробка» → шаблон «Квадратная» → перетащить в окно 2 PNG → двигать/масштабировать на лице → снизить насыщенность фона → «Текст» → шрифт «Underdog» → корешок: тот же логотип → «Сохранить» → коробка в шкафу.

### 3.2 Интерфейс (стол)
**Что видит пользователь:** белое (в тёмной теме — тёмно-серое) пространство 1280×720, обведённое рамкой, — ровно то, что игрок увидит на экране. Сверху внутри рамки — заблокированная полоса TopBar (48 px), её содержимое не редактируется (`hub/top_bar.gd` обязателен во всех играх; название игры, часы хода, чат, пауза, выход — подставляются сами).

**Инструменты (слева):** выбор, рука-панорама, зона, панель игрока, кнопка, счётчик, текст, картинка, лоток кубиков, журнал, фаза/ход.

**Элементы раскладки:**
| Элемент | Что это | Свойства |
|---|---|---|
| Фон стола | картинка/цвет/текстура | растяжение, затемнение |
| Зона | место для компонентов | вид: колода (стопка рубашкой), сброс (верхняя открыта), ряд, веер (рука), сетка, свободная; владелец: общий / у каждого игрока / у команды; масштаб карт; «свободная» (ручной режим) |
| Панель «Я» | моё место (обычно снизу) | портрет, имя, ресурсы, рука, свои зоны |
| Полоса соперников | повторяется для каждого другого игрока | авто-раскладка сверху/по бокам для 1–7 соперников; что показывать: число карт, ресурсы, открытые зоны |
| Команды | панель команд | название, цвет, счёт, состав |
| Кнопка | действие игрока | текст; событие «Нажата кнопка X» в логике; активна, когда логика разрешает (иначе полупрозрачная) |
| Счётчик | показывает переменную | число/шкала/иконки ×N |
| Текст | надпись, может подставлять переменные | «Раунд {раунд} из {всего}» |
| Лоток кубиков | где катаются `TossDie` | размер, кубики, кто бросает |
| Журнал | лог партии | (кнопка в TopBar «Журнал» добавляется автоматически) |
| Фаза/ход | крупная строка хода | пишется в `_top.info` TopBar |

- **Сетка 8 px**, привязка к краям/центрам других элементов, умные направляющие, якоря (элемент прилипает к краю/центру при другом соотношении сторон).
- **Число игроков меняется** — поэтому раскладка задаётся не «игрок 1, игрок 2…», а «Я» + «Соперники» (повторяющийся шаблон). Предпросмотр: переключатель «Игроков: 2…8».
- **Видимость** (решение владельца, MVP): у каждого элемента галочки «Кому виден»: всем / владельцу / ведущему / роли X / команде владельца / никому. Переключатель **«Смотреть как: Игрок / Ведущий / Роль X / Зритель»** над полем.
- **Свой экран роли** (после MVP): у роли кнопка «Отдельный экран» — копия общей раскладки, которую можно перестроить целиком (например, ведущий в «Опасных словах»).
- **Главная кнопка фазы** — по правилам проекта одна, снизу по центру; редактор подсвечивает, если автор поставил две «главные».
- **Тема**: автор выбирает 2 основных цвета; нейтральные и тёмная тема строятся автоматически (`cg_style.gd`). Предпросмотр в обеих темах — переключатель над полем. Проверка чек-листа: элементы не выходят за рамку и не перекрываются (красная обводка).
- **Ручной режим**: «свободная» зона — игроки перетаскивают компоненты мышью (`K12TableCard`, тени перетаскивания — `Net.ghost_received`), переворачивают ПКМ, тасуют кнопкой у колоды. Хост проверяет только, что компонент можно трогать этому игроку.

**Сценарий:** «Интерфейс» → «Зона» → в центр: колода «Основная» (вид — колода) и сброс → «Панель Я» снизу с веером-рукой → «Соперники» сверху: показывать число карт и очки → кнопка «Пас» → «Смотреть как: Соперник» — карт руки не видно.

### 3.3 Логика (гибрид блоков)
Подробно — раздел 5. **Что видит пользователь:**
- Сверху рабочего поля — **лента фаз** (таймлайн): «Подготовка → Ход игрока (Взять → Сыграть) → Конец раунда → …». Фазы добавляются, переименовываются, перетаскиваются; клик по фазе фильтрует события этой фазы.
- Слева — **палитра блоков** по категориям-цветам: События, Действия, Управление, Значения, Игроки, Карты и зоны, Кубики, Переменные, Конец игры. Поиск по названию.
- В центре — холст с **цепочками**: событие-шапка, под ним блоки, соединённые одной линией сверху вниз (порядок выполнения); ветвление «Если/иначе» и циклы — отступом с двумя-тремя выходами. Значения — округлые «пазлы», вставляемые в гнёзда блока; форма гнезда показывает тип (см. 5.5), неподходящее значение просто не встаёт.
- Справа — **переменные** (общие / у игрока / у команды, тип, начальное значение), **роли и команды**, **порядок ходов**, панель **Ошибки**.
- Мини-карта холста, зум, комментарии-стикеры, сворачивание цепочки, копирование (Ctrl+C/V между играми).

**Пример владельца** («если → ведущий → карта → открыть → игрок 1 → получает») в гибридной записи:
```
⚑ Когда [Ведущий] нажал кнопку «Открыть»
│
├─ Открыть [верхнюю карту] колоды «Улики» для [всех]
├─ Если  ( [свойство «цвет»] у [этой карты] = «красный» )
│   └─ Переместить [эту карту] в [руку] игрока [Игрок 1]
│  иначе
│   └─ Переместить [эту карту] в зону «Сброс»
└─ Передать ход [следующему игроку]
```

### 3.4 Элементы
**Что видит пользователь:** слева — библиотека элементов игры по группам (Колоды, Кубики, Жетоны и монеты, Ресурсы, Панели игроков), кнопка «+». В центре — крупный предпросмотр выбранного элемента (карта в натуральном масштабе, кубик можно бросить). Справа — свойства.

**Колода карт** (решение владельца: шаблон + таблица):
- Размер — один из 9 (таблица 3.4.1), скругление углов (общий `card_corners.gdshader`).
- **Рубашка** — картинка или шаблон; вариант рубашки по командам.
- **Шаблон лица** — мини-редактор слоёв (как на коробке): фон, картинка, текст, фигура; у текстового/картиночного слоя — привязка к колонке таблицы («{Название}», «{Цена}», «{Арт}»).
- **Таблица** — строка = вид карты: колонка «Копий», пользовательские колонки с типом (число, текст, картинка, цвет, да/нет). Колонки видны в логике как «свойство X у карты». Импорт CSV, вставка из буфера (из Google Таблиц/Excel).
- **Импорт готовых картинок**: папка PNG → по карте на файл; **лист-сетка** (как в TTS, напр. 10×7) → нарезка с указанием столбцов/строк и количества.
- **По командам** (решение владельца): флаг «Своя колода у каждой команды/игрока» — колода тиражируется, у копии свой цвет рамки/рубашки.
- Просмотр при наведении — крупный, рядом (правило проекта, как `gl_table.gd: _show_preview`).

**Кубики** — механика только `TossDie` (2D, бросок мышью, результат с хоста):
- MVP: d6. Грани — точки / числа / свои картинки/символы на каждой грани; цвет тела и точек; набор кубиков (например, «5 белых»).
- **По игрокам/командам**: «цвет игрока» / «цвет команды» вместо фиксированного цвета; у каждого свой набор.
- После MVP — d4, d8, d10, d12, d20 (нужно расширение `TossDie`).

**Жетоны и монеты**: форма (круг/квадрат/шестиугольник/своя картинка), лицо и оборот, номиналы (монеты 1/5/10), количество (или «без ограничения»), цвет по игроку. Для подсчёта лучше **ресурс** — число у игрока с иконкой (счётчик), а не сотня физических жетонов; редактор подсказывает это.

**Панель игрока (планшет)**: картинка + ячейки (зоны и счётчики на ней), у каждого игрока своя копия, цвет игрока.

**Фишки и поле-ходилка** — после MVP.

## 4. Модель игры (что хранится)

```
Игра
├─ мета: название, автор, версия, игроки min–max, время, описание, цвет
├─ коробка: шаблон, толщина, слои по граням, запечённые грани
├─ элементы: колоды (шаблон, таблица, рубашка), кубики, жетоны, ресурсы, панели
├─ раскладка: экран(ы), элементы с видимостью
├─ правила: роли, команды, порядок ходов, фазы, переменные, цепочки блоков
└─ ассеты: картинки, шрифты (по SHA-256, без дублей)
```

**Состояние партии** (на хосте, полностью сериализуемый словарь — для переподключения, «шага назад» в отладке и тестов):
- `zones`: id зоны (+ владелец) → упорядоченный список экземпляров компонентов; у экземпляра: id, вид (строка таблицы), лицом вверх/вниз, кому открыт, метки.
- `vars`: общие, у каждого игрока, у каждой команды.
- `turn`: фаза, текущий игрок, ведущий, номер хода/раунда.
- `pending`: ожидаемые ответы игроков (выбор, бросок) — продолжение цепочки (см. 5.2).
- `rng_seed`, `log`.

## 5. Логика: модель исполнения и блоки

### 5.1 Принципы
- Логика — **данные** (дерево блоков в JSON), исполняемые интерпретатором `CGInterp` **только на хосте**. Клиенты шлют действия `Net.send_action("cg", {...})`, получают свой view.
- Всё детерминировано от `rng_seed` хоста → воспроизводимые тесты и фазз.
- Ни один блок не исполняет произвольный код.

### 5.2 Исполнение
1. Игрок что-то делает (кнопка, клик по карте, перенос карты в зону, бросок, ответ на выбор) → клиент шлёт действие.
2. Хост находит обработчики события для текущей фазы; проверяет **условия «Разрешено, если»** (блок-страж у шапки). Нет разрешённого обработчика — действие отклоняется, игрок видит короткую подсказку «Сейчас нельзя: …» (текст стража).
3. Цепочка выполняется сверху вниз. **Ожидающие блоки** («Спросить игрока», «Бросить кубик игроком», «Подождать N с») приостанавливают цепочку: продолжение (стек «где мы») сохраняется в `state.pending`, партия ждёт ответа.
4. После выполнения — рассылка view каждому месту и зрителям.
5. **Сторож**: не более 10 000 шагов на одно действие и 1 000 итераций цикла; превышение → цепочка останавливается, в журнале «Логика зациклилась в блоке X» (в отладке — подсветка блока). Цепочки, запущенные событием из другой цепочки, — в очередь, глубина ≤ 16.
6. **Разрешённые действия**: интерпретатор умеет перечислить все допустимые действия места (по стражам и активным ожиданиям) — для подсветки активных кнопок/карт в UI, для фазза и будущего бота.

### 5.3 Ходы и фазы
- Порядок ходов (настройка): по кругу / по кругу от ведущего / одновременно (все действуют, фаза ждёт «Готов» от всех) / только ведущий.
- Фаза — состояние; блоки «Перейти к фазе», «Передать ход». События «Вход в фазу», «Выход из фазы».
- Встроенные: номер раунда, текущий игрок, ведущий (постоянный / по очереди / случайный — настройка роли).
- Часы хода TopBar (`turn_clock.gd`) работают от общего `turn_time` — событие «Время хода вышло» (после MVP — свои таймеры).

### 5.4 Набор блоков (MVP, ~45)
**События (шапки):** Начало игры · Начало раунда · Начало хода [игрок] · Конец хода · Вход в фазу [X] · Нажата кнопка [X] (кем) · Карта выбрана в зоне [X] (клик) · Карта перенесена из [X] в [Y] игроком · Кубики брошены · Время хода вышло · Переменная [X] изменилась (после MVP).
- У шапки игрока — страж **«Разрешено, если ⟨условие⟩»** и **«Только для [текущего игрока / ведущего / роли]»**.

**Карты и зоны:** Перемешать [зону] · Раздать [N] карт из [зоны] каждому в [зону игрока] · Взять [N] из [зоны] в [зону] · Переместить [карту] в [зону] (верх/низ/случайно) · Открыть / закрыть [карту] для [кого] · Показать [карту] крупно всем (2 с) · Вернуть все карты в [колоду].

**Кубики:** Бросить [кубики] игроком [X] (ожидание броска мышью) · Бросить автоматически · Значение кубика [N] / сумма / количество выпавших [значение].

**Игроки и ход:** Передать ход [следующему / игроку X] · Перейти к фазе [X] · Пропустить [игрока] · Выбыть [игрок] · Назначить ведущим [игрок].

**Спросить (ожидание):** Спросить [игрока] выбрать карту из [зоны] · выбрать игрока · выбрать вариант [кнопки] · ввести число [от–до]. Ответ доступен как значение «ответ».

**Переменные:** Установить [переменная] = ⟨значение⟩ · Изменить на ⟨±N⟩ · (у игрока/команды — с гнездом [кого]).

**Управление:** Если ⟨⟩ / иначе · Повторить [N] раз · Для каждого игрока · Для каждой карты в [зоне] · Подождать [N] с · Остановить цепочку.

**Сообщения:** Написать в журнал «текст {значения}» · Всплывающая подсказка [кому] · Звук из набора (общие `Sfx`).

**Конец игры:** Победа [игрок / команда / все] · Поражение [всех] · Конец партии — побеждает максимум/минимум [переменной] (экран победы — общий `victory_screen.gd`).

**Значения (вставки):** число, текст, да/нет · игрок: текущий / ведущий / сделавший действие / следующий / игрок N / случайный / «ответ» · карта: эта / верхняя в [зоне] / выбранная · свойство [колонка] у [карты] · количество карт в [зоне] · переменная · случайное число [от–до] · математика (+ − × ÷ мин макс) · сравнения (= ≠ < > ≤ ≥) · И / ИЛИ / НЕ · «есть карта со свойством … в [зоне]».

### 5.5 Типы и проверка ошибок
- Формы гнёзд: **число** — овал, **да/нет** — шестиугольник, **игрок** — круг с силуэтом, **карта** — прямоугольник с уголком, **зона** — скобки, **текст** — прямоугольник. Цвет блока — категория.
- Проверка «на лету», панель «Ошибки», клик — перейти к блоку:
  - ✖ пустое обязательное гнездо; ссылка на удалённый элемент/зону/переменную; фаза, в которую нельзя попасть; нет ни одного условия конца игры; переход «Передать ход» в режиме «одновременно».
  - ⚠ цепочка без шапки (не выполнится); событие кнопки, которой нет в раскладке; зона в логике, не размещённая на экране; «Повторить» больше 100.
- С ✖ нельзя запустить партию в пати (только «Проверить» с предупреждением); ⚠ не мешают.

### 5.6 Отладка («Проверить» — «Играть за всех»)
- Офлайн-партия (`Net.host_offline("custom:<id>")`) в окне редактора, места — живые hot-seat, переключатель мест сверху (Игрок 1 / Игрок 2 / Ведущий / Зритель) — без закрытия руки, это режим автора.
- Панель отладки справа: переменные и зоны (живые), журнал выполненных блоков, ожидания; кнопки **шаг назад** (снимки состояния перед каждым действием), «Заново», «Тот же расклад» (тот же seed), число игроков.
- Во вкладке «Логика» во время проверки — подсветка последних сработавших блоков и счётчик срабатываний.

## 6. Сохранение и формат

### 6.1 Папка игры
```
user://custom_games/<uuid>/
├─ game.json            # вся игра: мета, коробка, элементы, раскладка, логика
├─ assets/img/<sha>.png|jpg|webp
├─ assets/fonts/<sha>.ttf|otf
├─ covers/front.png back.png spine.png top.png   # запечённые грани
├─ thumb.png            # миниатюра для «Мои игры»
└─ history/<дата>.json  # 10 последних версий game.json
```
- `game.json` содержит `"format": 1` (версия схемы) — при изменении схемы миграция `CGPackage.migrate()`; поле `"game_version"` растёт при каждом сохранении.
- Ассеты адресуются SHA-256 содержимого — без дублей, легко проверить при передаче.
- Пользовательские ресурсы **никогда не грузятся через `ResourceLoader`** (`.tres`/`.tscn` могут нести скрипты): картинки — `Image.load_*_from_buffer`, шрифты — `FontFile.data`, описание — `JSON`.

Пример (сокращённо):
```json
{
  "format": 1, "id": "3f2c…", "game_version": 14,
  "meta": {"title": "Улики", "author": "Huffle", "players": [3, 6], "time": "20 минут",
           "description": "…", "color": "#3a5f8f"},
  "box": {"template": "square", "thickness": 0.06, "faces": {"front": [{"type": "image", "asset": "a1b2…", "pos": [0.5, 0.4], "scale": 1.2, "rot": 0, "fx": {"opacity": 1, "brightness": 0, "saturation": -0.2}}]}},
  "elements": {"decks": [{"id": "clues", "size": 3, "back": "c3d4…", "columns": [{"id": "color", "type": "text"}], "rows": [{"copies": 4, "color": "красный", "art": "e5f6…"}]}]},
  "layout": {"screens": [{"id": "main", "items": [{"kind": "zone", "id": "draw", "deck": "clues", "view": "pile", "rect": [560, 280, 160, 240], "owner": "shared", "visible": ["all"]}]}]},
  "rules": {"roles": [{"id": "leader", "name": "Ведущий", "mode": "rotate"}], "teams": [], "turns": "round",
            "phases": ["setup", "turn"], "vars": [{"id": "score", "scope": "player", "type": "number", "init": 0}],
            "chains": [{"event": {"type": "button", "button": "open", "by": "role:leader"}, "blocks": […]}]}

### 6.2 Пакет для сети
- Пакет = zip папки без `history/` (`ZIPPacker` в памяти), хэш пакета = SHA-256.
- Ограничения: пакет ≤ 64 МБ; картинка — до 2048 px по длинной стороне (больше — уменьшается при импорте с предупреждением); шрифт ≤ 10 МБ; только расширения png/jpg/webp/ttf/otf/json. Распаковка проверяет пути (без `..`, абсолютных путей), размеры и формат JSON по схеме.

## 7. Интеграция с архитектурой проекта

### 7.1 Хаб и шкаф
- `HubGames.LIST` остаётся `const`. Добавляется `HubGames.all()` = встроенные + пользовательские из `CGLibrary.list()` (запись того же формата: `id = "custom:<uuid>"`, `title`, `players`, `time`, `description`, `scene = "res://games/custom/ui/main.tscn"`, `color`, `thickness`, `custom = true`). Места, где хаб перебирает `LIST` (шкаф, окошки VR, выбор игры в пати), переходят на `all()`.
- `game_box.gd: cover_texture()` — для `custom` берёт текстуры из `covers/` папки игры (загрузка через `Image`), размер коробки — из шаблона.
- Новые пользовательские коробки занимают свободные ячейки шкафа (`shelf_config.gd` уже умеет добавлять новые игры, если есть место); у коробки маленькая метка «своя игра».

### 7.2 Сеть (`Net`)
- Одна новая ветка в `net.gd` для всех пользовательских игр: `cg = CGRules.new(); cg.load(def); cg.new_game(players, settings)`; в `_handle_action` — `cg.act(seat, kind, arg)`; view — `cg.view_for(seat)` / `cg.view_for_spectator()`. Правка `net.gd` — только эта ветка и передача пакета (файл общий, согласовать с параллельными сессиями).
- Настройки — ключи с префиксом `cg_`: `cg_game` (uuid + хэш пакета), `cg_opts` (после MVP — настройки автора).
- Офлайн: пользовательские игры ведут себя как игры из `Net.LOCAL_GAMES` (hot-seat, ботов нет) — проверка `party_game.begins_with("custom:")`.
- **Приватность view**: закрытая карта в чужом view — только «рубашка» без id вида; порядок колоды клиентам не передаётся; переменные с видимостью «владельцу» — только владельцу.

### 7.3 Передача игры от хоста
1. Хост выбирает пользовательскую игру → в данных лобби `cg_game = {uuid, hash, size, title}`.
2. Клиент ищет `user://custom_cache/<hash>.zip`; нет — запрашивает у хоста.
3. Хост шлёт пакет кусками по 48 КБ надёжными RPC (влезает в лимиты Steam P2P и ENet), по очереди клиентам, с паузами, чтобы не забить канал чата/лобби.
4. Клиент проверяет хэш и распаковывает (с проверками 6.2), показывает в лобби «Загружается игра: 3,2 / 12 МБ». Хост видит у игроков значок загрузки; «Начать» доступна, когда у всех готово.
5. Кэш — до 1 ГБ, старые пакеты удаляются по дате использования. Полученная игра **не попадает в шкаф и не редактируется** клиентом (MVP); играть в неё можно только когда её выбрал хост.
- Зритель и переподключившийся игрок — тот же механизм.

### 7.4 Безопасность пакетов
Пакет — чужие данные с чужого компьютера: только JSON, картинки, шрифты; никакого кода; интерпретатор ограничен сторожем шагов; лимиты размера; проверка путей zip; текст из пакета вставляется в UI без BBCode-разметки.

### 7.5 Стол пользовательской игры (`games/custom/`)
- Структура по образцу `games/perudo/ui/`: `cg_app.gd` (меню/лобби/стол), `cg_lobby.gd` (игроки, команды, роли, статус загрузки), `cg_table.gd` — **строит стол из раскладки** игры; `cg_style.gd` — стиль из 2 цветов автора, светлая/тёмная тема.
- Общие компоненты без исключений: `TopBar.make(...)` (обязателен), `K12TableCard` для всех карт (лицо — запечённая по шаблону текстура, рубашка — `back_drawer`), `TossDie` для кубиков, `LeaveGuard` для выхода, `victory_screen.gd` для конца, `card_corners.gdshader`, крупный просмотр при наведении.
- Лица карт запекаются при загрузке партии (шаблон + строка таблицы → текстура в `SubViewport`), кэшируются в памяти.

tests/               test_custom_rules.gd, test_custom_package.gd, test_editor_model.gd
```
- Холст логики: собственный `Control` (панорама/зум как у полей-ходилок), блоки — свои контролы с гнёздами. `GraphEdit` из Godot не подходит под вложенные значения-пазлы; его можно взять только для прототипа.
- Модель редактора (данные + команды undo) отделена от UI и тестируется headless.

## 9. Риски

| Риск | Чем грозит | Что делаем |
|---|---|---|
| Объём (по сути отдельный продукт) | годы вместо месяцев | жёсткий MVP, этапы с играбельным результатом каждый |
| Логика непонятна обычному игроку | редактор не используют | гибрид «фраза» вместо проводов, примеры, проверка ошибок по-человечески, отладчик |
| Блоков не хватает для реальных игр | авторы упираются | сначала собрать 3 игры сборника (Перудо-подобная, простая карточная, «Больше-меньше») только блоками — пробел виден до UI |
| Ожидания и переподключение | зависшие партии | продолжения в сериализуемом состоянии, тест «сохранить/загрузить посреди ожидания» |
| Большие пакеты по Steam | долгий старт, обрывы | лимиты, сжатие картинок при импорте, докачка с куска, кэш по хэшу |
| Чужой пакет — вредоносный | падение/исполнение кода | только данные, без `ResourceLoader`, сторож шагов, проверка zip |
| `net.gd` — общий монолит | конфликты с другими сессиями | одна изолированная ветка `cg`, передача — отдельный файл `cg_transfer.gd` |
| Производительность (много карт, запекание лиц) | лаги | запекание один раз при загрузке, пул `K12TableCard`, ограничение 300 компонентов в MVP |
| Права на пользовательский арт | претензии при публикации | ответственность автора, поле лицензии, нет публичного каталога |
| Шкаф не вмещает новые коробки | коробки «исчезают» | шаблоны только известных размеров, уже существующее уплотнение шкафа |

## 10. Этапы реализации

Каждый этап заканчивается проверками проекта: тесты, compile, фазз (`--audio-driver Dummy`), скриншоты в обеих темах 1280×720, запись в `REVIEW_QUEUE.md` для перекрёстного ревью.

1. **Ядро логики (headless).** `cg_def`, `cg_rules`, `cg_interp`, каталог блоков; 3 игры, собранные вручную в JSON; `tests/test_custom_rules.gd` + фазз по «разрешённым действиям». Готово: игры доигрываются до победы, сторож ловит зацикливание, view не раскрывает чужие карты.
2. **Стол пользовательской игры.** `games/custom/ui/`: стол из раскладки, TopBar, `K12TableCard`, `TossDie`, лобби с ролями/командами; ветка `cg` в `Net`; офлайн и ENet. Готово: JSON-игра играется вдвоём по ENet, переподключение работает.
3. **Пакет, передача, хаб.** `cg_package`, `cg_library`, `cg_transfer`; `HubGames.all()`, коробка из `covers/`, место в шкафу; прогресс загрузки в лобби. Готово: клиент без игры докачивает и играет; Steam — проверить отдельно, ENet не считать проверкой Steam.
4. **Оболочка редактора + «Элементы».** Вход через ТВ, «Мои игры», вкладки, undo/redo, автосохранение; колоды (9 размеров, шаблон + таблица, CSV, лист-сетка), кубики d6, жетоны, ресурсы, панель игрока.
5. **«Интерфейс».** Холст 1280×720, зоны, «Я»/соперники, кнопки, счётчики, видимость, «Смотреть как», проверки перекрытий, темы.
6. **«Логика» + «Проверить».** Холст блоков, лента фаз, палитра, переменные, проверка ошибок, режим «Играть за всех» с отладкой и шагом назад.
7. **«Коробка».** 3D-коробка, шаблоны, слои, трансформации, коррекция, текст, встроенные шрифты, запекание граней.
8. **Полировка MVP.** Шаблоны «Карточная»/«С кубиками», короткое обучение (подсказки при первом открытии вкладки), «Что нового», ревью Codex.
9. **После MVP** — по порядку: свои экраны ролей → бот «случайный допустимый ход» → поле-ходилка и фишки → d4–d20 → настройки автора в лобби → экспорт/импорт `.pgame` → Workshop.

Оценка порядка: этапы 1–3 — фундамент, без которого вкладки редактора нечего сохранять и негде играть; поэтому «Коробка» (самая наглядная) идёт после логики, хотя в редакторе она первая вкладка.
