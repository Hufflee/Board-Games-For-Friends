# Просмотр комнаты участника пати

Основание: шесть незавершённых пунктов раздела8 пакета27.10. Это просмотр неоновой комнаты из хаба; игровые экраны и их приватные состояния в снимок не входят.

## Ожидаемое поведение

- Рядом с участниками пати в хабе — минималистичный глаз с подсказкой. У собственного имени в режиме просмотра — домик для возврата. Текущий наблюдаемый глаз не дублируется.
- Сверху имя владельца, по краям мягкое голубое свечение. Видны его шкаф, позы и порядок коробок/фигурок, выбранная перед ним игра, изменения редактора в реальном времени.
- Переключатель «Отключить действия <имя>» сохраняет просмотр шкафа, но не повторяет удерживаемую игру и дальнейшие действия владельца. В этом режиме можно локально нажимать коробки и читать их описания.
- Чужую расстановку нельзя редактировать или записывать в собственный shelf_layout.cfg. Возврат домой восстанавливает собственную расстановку, её предпочитаемые места и обычное управление. Состояние удалённого редактора не открывает собственный редактор.
- Отключение наблюдаемого, выход из пати и исчезновение его снимка возвращают в собственную комнату без устаревших отложенных callbacks. Переход между участниками не накапливает копии комнат и обработчики.

## Граница реализации

Net хранит только публичный снимок комнаты каждого подключённого peer и пересылает его участникам той же пати. Клиент не может выдать свой снимок за другого peer. Снимок содержит только разрешённую геометрию/ID/позы шкафа и выбранный публичный ID игры; не сериализовать весь Net, Prefs, Node или игровой view. Проверять типы, размеры коллекций, ID и конечность чисел. Не передавать путь файла/ресурса от отправителя в load().

NeonRoom предоставляет явные операции чтения публичного снимка и временного применения удалённого состояния без сохранения. Локальный снимок для возврата хранить отдельно от резервной копии редактора. Публиковать изменения с ограниченной частотой и только при фактической разнице; финальное состояние отправлять после действия. Поздний вход получает уже известные публичные снимки. API должно учитывать единый порядок фигурок/коробок после shelf_push.

Основные файлы: hub/hub.gd, hub/neon_room.gd, games/king_of_12/net/net.gd; отдельный helper публичного снимка допустим для ограничения объёма изменений. Сначала завершить и принять shelf_push, чтобы два исполнителя не меняли neon_room одновременно. Сохранить резервную копию крупных изменяемых скриптов в backups/.

## Минимальная проверка

1. Валидный снимок проходит, неправильный peer/типы/ID/бесконечные числа и лишние секретные поля не попадают в распространённое состояние. Есть ограничение размера.
2. Настоящий ENet host + два клиента: каждый видит нужную комнату, текущие изменения шкафа и выбранную коробку; переключение участника/домой, отключение отслеживания, поздний вход, выход наблюдаемого и разрыв пати проверены с ожиданием состояния каждой стороны.
3. Собственный файл шкафа до/после просмотра одинаков, чужой файл не меняется от локального клика. Домой возвращается собственная конфигурация без потери ID.
4. Кнопки работают мышью; кадр1280×720 с именем/свечением/глазами/домиком просмотрен. Компиляция и адресная регрессия пати/шкафа после изменения; без повторения уже принятых незатронутых игровых пакетов.

Все запуски Dummy и с отдельным APPDATA; Steam в этом сценарии не выдавать за проверенный транспорт. Экспорт, коммит и публикация не поручены.
