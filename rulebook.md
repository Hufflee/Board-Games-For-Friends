# Rulebook — правила из повторённых ошибок

- **Проверяющий многократно назывался Sol low без проверки фактического effort** → назначение роли текстом не настраивает модель. При создании проверяющего явно задавать `reasoning_effort=low` и проверять метаданные `turn_context`; не называть проверку low при фактическом medium. Для ограниченной задачи не наследовать огромную историю (`fork_context=false`), передавать короткий handoff. Проверка: модель/effort в журнале соответствуют разрешённому владельцем распределению. Аудит29.10нашёл medium у обоих исполнителей; это не обесценивает результаты тестов, но требует исправления описания конфигурации.

- **В PowerShell несколько раз передана маска пути непосредственно в rg (`hub/chat*.gd`)** → PowerShell не раскрывает её для native-команды. Передавать каталог и `-g '*chat*.gd'`, либо сначала `rg --files`. Проверка: нет ошибки os error123; отсутствие совпадений не путать с ошибкой пути. (Codex,28.10.2026)

Если нейросеть (Claude или Codex) совершила **одну и ту же ошибку второй раз** — сюда добавляется правило.
Формат: **ошибка** → как делать правильно → как проверить. Кто и когда — в конце строки.

- **Повторно отправлены блоки apply_patch к одному файлу в обратном порядке разделов, из-за чего контекст не найден** → располагать hunks в порядке строк файла сверху вниз либо разделять правки на отдельные вызовы. Проверка: сначала проверить актуальные заголовки, после применения убедиться, что весь пакет принят; не считать частично подготовленный патч сохранённым. (Codex, 2026-10-27)

- **SceneTree-тест статически подтягивает UI-класс, использующий Sfx/Diag, до регистрации autoload и получает ложные Compile Error** → загружать такие UI/Net-скрипты динамически внутри отложенного запуска после инициализации дерева; не ссылаться на них статическим типом/классом в заголовке теста. Проверка: реальные игровые сценарии исполняются, в логе нет Identifier not found: Sfx/Diag; код выхода0 без выполненных проверок успехом не считается. (Codex/Sol, 2026-10-27)

- **Повторное использование тестового APPDATA после аварии/принудительного завершения скрывает UI под окном диагностики и даёт ложные ошибки кликов** → для чистого повторного UI-прогона использовать новый изолированный профиль либо явно обработать диагностическое окно настоящим вводом; пользовательские настройки и историю не удалять. Проверка: стартовый кадр не содержит сообщения о предыдущем падении, ожидаемый элемент реально получает ввод; прежние отрицательные журналы сохраняются. (Codex, 2026-10-27)

- **Перепутан значок атаки со здоровьем на карте, затем ошибка повторена в отчётах** → перед реализацией читать спорный текст на полноразмерном изображении; OCR и прежний собственный каталог не заменяют изображение. Для спорной механики сверять соответствующую редакцию карты по первоисточнику. Проверка: ожидаемые показатели и пороги в тестах совпадают с напечатанными значками. Пример: Гибельный получает атаку за души, а не здоровье. (Codex, 2026-10-26)

- **Скриншоты Godot в папку Temp/scratchpad иногда не сохраняются** → сохранять в `build/shots` (`OUT=…/build/shots`), потом обрабатывать оттуда. Проверка: файл `build/shots/*.png` появился. (Claude, 2026-10-24)
- **`:=` от значения Variant (элемент Array/Dictionary) — ошибка компиляции «Cannot infer the type»** → явный тип: `var x: int = arr[i]`, у переменной цикла — тоже. Это относится и к составным логическим выражениям с `Dictionary.get(...)`: указывать `: bool` (повтор Codex, 26.10, `printed_eternal`). Проверка: `tools/_fuzz/compile.tscn` → `SCRIPTS N` без ошибок. (Claude, 2026-10-24; уточнение Codex, 2026-10-26)

- **Запись патчноута пропускается после переименования «В разработке» при релизе** → перед правкой читать текущие заголовки; если раздела нет, создать новый «В разработке» перед первой выпущенной версией. Проверка: новая запись находится именно в новом разделе, старый релиз сохранён. (Codex, 2026-10-24)
- **Плотный «минифицированный» GDScript: несколько операторов через `;`, без пробелов вокруг `=`/`,`, без комментариев** (hub/private_hand.gd, затем hub/player_stats.gd и hub/match_metrics.gd) → писать как остальной проект: один оператор в строке, пробелы вокруг операторов и после запятых, типизация, док-комментарий `##` в начале файла и у неочевидных функций. Проверка: перед сдачей просмотреть новый файл — нет ли `;` и строк длиннее ~140 символов с несколькими действиями. (Codex, 2026-10-24)

- **gdformat переносит многострочный lambda-аргумент вложенного вызова с недопустимым для Godot отступом** → выносить такой callback в именованный метод; совпадение AST gdtoolkit не заменяет компиляцию настоящим Godot. Проверять журнал compile, а не только код выхода (сцена compile может завершиться с 0 при ошибках отдельных скриптов). (Codex, 2026-10-25)

- **В ручном UI-тесте несколько раз пропущена душа в награде босса** → перед ответом выписать все значки нижней строки карты: монеты/лут/сокровище и души; отдельно выписать обязательный текст смерти. Перед «Эффект выполнен» проверить начисление каждой части и происхождение души. Проверка: план содержит все напечатанные награды, souls_cards ссылается на убитую карту; неполный ручной прогон не засчитывать как корректную партию. (Codex, 2026-10-26)

- **Повторно прочитан недописанный JSON при обмене между тестовыми процессами (UI-ответ, затем сетевой снимок)** → существование файла не означает завершение записи. Писать во временный файл и атомарно заменять целевой; при постоянно обновляемых снимках читать с ограниченным повтором до корректного JSON. Проверка: обмен не падает на пустом/частичном файле; сбой harness не объявлять ошибкой игры или чистым прогоном. (Codex, 2026-10-26)

- **Двусмысленное «неатакуемый слот» у Пипа было несколько раз перенесено в TODO/отчёты как постоянный запрет атаки** → сверять контекст слота с оригиналом: незанятая текущим боем ячейка не даёт карте постоянного иммунитета к атакам и не означает расширение поля. Проверка: размещение не затрагивает текущий бой, нижняя карта сохраняется, выложенный Утопец остаётся доступен обычной атаке. (Codex, 2026-10-26)

- **Сетевая проверка прочитала старый снимок клиента после успешного ожидания только хоста (повторено дважды)** → ждать нужное состояние у каждой стороны, чьи данные затем утверждаются. Проверка: перед assert по клиенту есть ожидание именно клиентского поля/версии; прежние неудачные логи сохраняются. (26.10.2026)
- **Повторно угадано неверное имя теста** → сначала сверить путь через rg --files tests, затем запускать существующий файл. Проверка: в итогах отделять Failed loading resource от провала проверок игры. (26.10.2026)

- **Угаданное имя ручной операции monster_dc использовано в задании и затем в тесте, хотя сервер его не поддерживает** → до подготовки сценария сверять OPS/EXTRA_OPS панели и ветки FSRules._effect; здесь правильная операция temporary_monster_dc. Проверка: положительный контроль из другой карты действительно изменяет целевое свойство, провал не считается игровым багом при неизвестном op. (Codex/Sol,27.10.2026)

- **Повторно использован вывод типа := от Variant (UIfind_children черездинамическое поле и вектор из нетипизированного цикла)** → задавать тип Array у результатов динамических вызовов и Vector2 у переменных цикла перед векторными операциями. Проверка: compile и фактический запуск изменённого UI без Cannot infer the type. (Codex,2026-10-27)
